# 质量校验与独立审校

> 原则：**能让脚本判的，绝不靠眼睛；只有脚本判不了的（好看/好读），才靠人眼。**

---

## A. 自动校验：一条命令

```bash
node tools/gate.mjs             # 构建 + 保真/闭合/结构 + 标签 + 冒烟，写 QA.md + QA.json
node tools/gate.mjs --shots     # 追加一套分区截图（只出证据，不做断言）
node tools/gate.mjs --no-smoke  # 没装 Chrome 时先跑其余层（会记「未验证」，不许说通过）
```

退出码：**0** 自动层全绿 / **1** 有失败（含 AI 审校有「严重」、有该跑没跑的层）/ **2** 环境没准备好（缺原文）。
缺 Chrome 时 smoke 变「未验证」，退出码也是 1——**没跑过的层不许算绿**；确属有意跳过（如只改译文先看看保真）就加 `--allow-partial`，`QA.md` 仍记「部分未验证」。

`gate.mjs` 把每一步的退出码、用时、关键数字、`index.html` 与 `data/` 的 sha256 写进 `QA.md`。
**内容一变哈希就变**，旧的 `QA.md` 不能再当这次交付的证据——这条挡住了「改完没重建」和「审校基于旧构建」两类假通过。

### 1. 保真度（check-content A/B/C）

- 我写的每句英文，必须在原文里**逐字**找得到 → 抓抄错、抓"顺手改写"。
- 原文每句，必须在英文列里出现 → 抓漏译。
- 中文列不允许空值。
- **任何一字之差都是错误**，只有两类例外：①纯空白差异（`,"passing` vs `, "passing`，脚本自动识别，不用手配）；②在 `meta.typos[].quote_en` 或 `meta.allowed_diffs` 里显式备案。

**红线**：`often` 译成"总是"、`frequently outperformed` 译成"全面胜出"、`roughly 2x` 译成"快了一倍"——这类**程度词漂移**，
脚本只能给出候选（见 §5 漂移扫描），最终靠审校，`07-cases.md` 里有真实对照。

### 2. 句对平衡（check-content D）

每个 `data-k` 必须恰好出现 **2 次**。不等于 2 → 左右两栏某一边漏了。
顺带查：每个 `data-link` 出现次数应为偶数（一次引用 = 两栏各一处）。

### 3. 引用闭合（check-content E/F/G/H）

- `data-term` / `data-link` / `data-note` 的 id 必须都在对应数据文件里，否则**报错**（以前只打印不报错）。
- 译注在正文里的出现顺序必须与 `meta.notes` 数组顺序一致（上标编号=阅读顺序）。
- `data-link` 数量应为"引用点 ×2"；出现 `<a data-link`（没补 href）说明 build 的 linkify 没生效。
- `meta.link_stats.refs` 与页面实际文内锚点数对不上 → 警告（口径见 `02-data-contract.md`）。
- 术语表里"业务上存在但正文没出现"的 key 是允许的，报告出来人工判断即可。

### 4. 结构对账（check-content S）

专抓"数据与原文对不上"：

- 每个 `fig` 块引用的 id 必须在 `figures.json` 里；反过来，登记了却没被引用也要报；
- 同一张图被引用两次 → 报错（图片容易渲染两份）；
- `article.md` 里的 `![` 数多于登记的配图数 → 警告「是不是丢图」；
- `article.md` 里有 markdown 表格行、但正文没有 `table` 块 → 警告「表格被吞了」；
- 阶段 0 存了 `data/survey.json` 时，把「勘察时有多少图/表/代码/链接」和现在的数据再比一次。

### 5. 漂移扫描（check-content W，警告级，不拦交付）

- **程度词**：原文有 often / always / never / roughly / only / most / some / tends to，中文里找不到对应说法；
- **数字**：原文的阿拉伯数字在译文里消失（`2x faster → 一半时间` 这类等价说法已加白名单）；
- **术语**：术语卡的中文名与正文首次出现的译法不一致（正文用英文缩写 SAST 不算不一致）。

输出是**候选清单**，写进 `QA.md` 交给审校逐条判——不是判决书。加 `--strict-drift` 才升级为错误。

### 6. 标签平衡（check-tags）

`div/p/ul/li/span/a/b/figure/details/section/table/tr/td/th` 等开闭必须相等。
不相等 = 你在 JSON 里写的行内 HTML 漏了闭合（最常见的：`<b>` 和 `</b>` 跨句对错配）。

### 7. 交互冒烟（smoke，20+ 项，随 data 动态生成）

模式切换 ×3、字号、目录开合、句级联动（两侧同时 `.hl`）、点击钉住、左右句对平衡、
动图/静帧切换、静帧切回、放大/关闭、链接可点（`http` + `target=_blank`）、
**每张图只渲染一份**、图注折叠数、延伸阅读卡数、术语表条数、数据表 / 表格单元 / 附录代码块 / 视频入口数量、无模板残留。

任何一项 FAIL 都别交付。其中"每张图只渲染一份"专抓 `[hidden]` 被覆盖的坑。
Chrome 路径由 `tools/chrome.mjs` 自动探测（macOS / Linux / Windows），可用 `CHROME=` 覆盖。

### 7.5 视频与云端（v2.1.0）

- `smoke` 的「视频播放入口」数的是 `.fig-bar .vbtn`（原站链接），有视频的页面必须保留它，否则冒烟会红。
- 内嵌视频：headless 探针查 `readyState=4` / `duration` / `videoWidth`，并 seek 到中段截一帧（不是全黑）。
- 云端版：必须用支持 Range 的服务器打开（`file://` 测不出 206）；`curl -H "Range: bytes=0-1023" -I` 应是 206；
  首屏 `performance.getEntriesByType('resource')` 里不应有 `.mp4`。
- `node tools/publish.mjs` 打印的两个体积要记进 QA/交付说明；单文件 > 10 MB 先回去压缩。
- **媒体预算**：发布前跑 `python3 tools/slim-media.py --dry`，单图 ≤ 260 KB、单页图片合计 ≤ 1 MB；
  超了先回去瘦身（规则见 `08-media-cloud.md` §0），别靠"反正能打开"糊过去。

### 8. 截图人眼过（shots）

必须看的三处：
- **首屏**：标题两栏是否错位、速览卡是否溢出
- **一张配图区**：图是否重复、图注是否压到正文
- **附录**：12 张卡片高度是否参差、长锚文本会不会撑破格子

还应该抽看：
- **深部区块**：偏移 >19500px 的区块会被自动单独渲染成 `s_iso_*.png`（长文后半段最需要人眼）
- **单语模式**：EN / 中 各截一张。截图前注入 `<script>try{localStorage.clear()}catch(e){}</script>`，否则 headless 会把上次的「双语」恢复，两张截图会一模一样（见 05-pitfalls 第 20 条）
- **数据表 / 代码块 / 视频图**：表格在窄屏是否横向滚动、代码块折叠是否正常、视频图是否有「看演示视频」入口

> 截图只能验"静态布局"。过渡/动画效果在无头渲染里不推进，别用截图判断功能是否正常（见 05-pitfalls 第 3 条）。

## B. 独立审校（阶段 6）

**派 fresh subagent**（不要 fork——它会继承你的自我合理化），明确要求"只挑错、不改文件"。
把 `references/07-cases.md` 一起给它：先看「允许的改写」，避免把正确译法报成错误；再看「必须抓的错」当对照。

### 提示词模板

```
你是这篇中英对照阅读版的独立审校。任务是挑毛病，不要改文件。

背景：<项目路径>
- 英文原文（权威）：data/article.md
- 逐句对照数据：data/part-1.json … part-N.json
- 术语表 / 链接卡 / 图解读 / 导读译注：data/*.json
- 最终页面：index.html（不要整份读，用 grep 定位）

目标读者：完全没接触过 <领域> 的 <角色>。用户要求「让小白看懂」且「翻译高水平」。

请做四件事：
1. 准确性抽查（最重要）：挑 30 组左右句对，覆盖每个 part、每种句式（长句、插入语、
   程度词 often/most/roughly、专有名词句）。逐条对照，判断：走样 / 漏限定词 /
   因果译反 / 术语误译。只报真问题。
2. 外行可读性：找出「即使有术语表仍会卡住」的句子（连续抽象名词、指代不清的「它/这」、
   英文长定语），每条给出更通俗的中文（保留原意与语气）。
3. 一致性：术语译名是否统一；<核心概念> 的不同叫法是否会让读者误以为是两回事。
4. 事实与引用：数字、模型名、命令名、链接锚文本是否与英文列一致。
5. **按版本核对**：文章若讲 v1→v2 的演进，导读/对比卡必须按版本分别写，不能把早期做法和最终做法混成一句（这类矛盾读者一进正文就会发现）；同时核对口径——`over 20x` 指成本还是时间？

输出格式（严格）：
## 严重（影响理解或属误译）
- [位置 part-x 第 y 句对] 问题 / 原文 / 现译 / 建议
## 中等
## 轻微
## 一致性检查结果
## 总体判断（一句话：能不能交给外行读？还差什么？）

要求：每条必须能指到具体文件与句子（用英文首词定位）。最多 20 条，宁缺毋滥。
```

### 实测有效的小技巧

- 让审校**先报"一致性检查结果"再报"总体判断"**，它会因此真的去核，而不是泛泛而谈。
- 明确写"只报真问题"，否则会给你 40 条标点偏好。
- 收到报告后按严重度分批改，**用脚本批量替换**并打印"命中 N 处 / 未命中列表"，
  未命中的说明你记错了原文，逐条确认。
- 改完重跑 A 全部 6 项；审校基于旧构建，必须按新文本复核。

## C. 交付门槛（全部满足才交）

**自动层**（`gate.mjs` 退出码 0，且 `QA.md` 的「自动验证」= 通过 / 部分未验证要逐项交代）：

- [ ] `check-content`：错误 0（英文差异只能是空白差异或已备案）；句对全部成对；[T] 表格单元 0 缺失；[S] 结构 0 错误
- [ ] `check-tags`：全平衡
- [ ] `smoke`：全 PASS（含数据表 / 代码块 / 视频入口数量）；没跑就不算通过
- [ ] **数据落地门禁**：links / glossary / figures 都已交付、条数与 SPEC 一致，且 `index.html` 是在这之后重建的
      （`gate` 会重跑 build，所以只要 gate 在数据齐之后跑过，这条自动成立）

**AI 层**（派 fresh subagent，报告存 `QA-review.md`）：

- [ ] 「严重」条目 = 0；中等/轻微逐条处理或写明确不采纳的理由
- [ ] 漂移扫描（W）的候选清单逐条判过，不是整段忽略

**人工层**（看完后用 `--confirm` 登记，登记时绑定哈希）：

- [ ] 首屏 / 配图 / 附录 三张截图人眼过
- [ ] EN / 中 单语模式各截一张：标题与补充层没有残留另一语言
- [ ] 术语一致性：正文与术语卡无两套叫法（`grep` 几个关键译名，出现次数符合预期）
- [ ] 原文笔误、歧义句、区域受限链接 —— 三栏备案齐全
- [ ] 文件可在任意浏览器双击打开，断网可用
- [ ] 一句自评：**关掉页面，能不能凭它复述原文的论证链？**
